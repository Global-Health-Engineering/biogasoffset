# Biogas Carbon Offsetting: Uncertainty and Overcrediting Analysis

This repository accompanies the master's thesis *"Determining Uncertainties and Overcrediting in Biogas-based Carbon Offsetting Projects"* by Lukas Walker (ETH Zurich, 2025). It contains the dataset, the data analysis scripts and the simulations used to evaluate emission reduction calculations in household biogas offset projects under different carbon crediting methodologies.

## Disclaimer

This repository was created as part of a master's thesis at ETH Zurich and is intended for academic and illustrative purposes only. While efforts were made to ensure accuracy, the analyses and conclusions presented here may contain simplifications, assumptions, or data limitations. ## Thesis Context

The thesis investigates the accuracy and transparency of carbon credits generated by biogas projects, particularly focusing on:
- **Quantifying overcrediting** in emission reduction claims,
- **Estimating uncertainty** in key input parameters,
- **Recommending improvements** for credit verification processes.

It draws on a manually reconstructed dataset of 13 household biogas projects (14 registry entries, as one project is registered with both the CDM and the Gold Standard) in China, India, Nepal and Vietnam, using three methodologies:
- CDM AMS-I.E
- CDM AMS-III.R
- Gold Standard TPDDTEC

## Repository Structure

### 📊 Notebooks
- **`MC_simulation.ipynb`**: [primary] Implements Monte Carlo simulations to evaluate uncertainty and overcrediting across methodologies.
- **`Other Diagrams.ipynb`**: [secondary] Contains visualizations and supplementary diagrams used in the final presentation.
- **`extract_non_empty_cells.ipynb`**: [secondary] Counts the non-empty cells of each project's raw Excel files.
- **`extract_raw_filesize.ipynb`**: [secondary] Explores dataset completeness and potential metadata patterns via file characteristics.

### 📁 Data
- **`methodology_data.xlsx`**: Primary dataset, transcribed by hand from the registry documents. Sheet `data` holds one row per variable and one column per monitoring period (and component project activity); the first three columns give the variable name, unit and description. Sheets `CDM Projects Selection` and `GS Projects Selection` list every screened project with the reason it was included or excluded.
- **`codebook.csv`**: Variable list for `methodology_data.xlsx`. `position` is the Excel row in sheet `data` and the column number in the selection sheets; `n_values` is the number of monitoring periods with a value; `note` flags variables that are empty everywhere or whose name occurs in more than one row.
- **`scopus_lit_review_fnrb.xlsx`**, **`scopus_lit_review_functional_devices.xlsx`**: Scopus search results with the search strings used, and the values read from the relevant papers (fNRB, share of functioning digesters). Abstracts were removed from the exports for copyright reasons; titles and DOIs are kept.
- **`raw_data/`**: The registry documents are not included. [`raw_data/README.md`](raw_data/README.md) lists every project with links to its registry page.

### 🛠 Utilities
- **`util.py`**: Helper functions for data extraction from Excel using `xlwings`, statistical sampling (triangular distributions), and plotting methodology comparisons.

## Usage

Requirements: Python 3 with `pandas`, `numpy`, `scipy` (< 1.14, `Other Diagrams.ipynb` uses `scipy.integrate.simps`), `scikit-learn`, `matplotlib` and `xlwings`. `xlwings` drives a local Microsoft Excel installation, so the notebooks run only on Windows or macOS with Excel installed.

To reproduce the analysis:
1. Run `MC_simulation.ipynb`. It copies `methodology_data.xlsx` to `methodology_data_MC_<timestamp>.xlsx` and writes the simulation results into that copy; the original file is not changed. Save the copy in Excel when the notebook is done.
2. In `Other Diagrams.ipynb`, set `excel_file` to the name of that copy, then run it.
3. The two `extract_*` notebooks need the raw files in `raw_data/` (see `raw_data/README.md`) and write into `methodology_data.xlsx` directly.

## Known issues

The code was written for the thesis and is published as it was used, apart from the data changes described above. It wasn't designed with future extensions in mind:
- Cell 5 of both `extract_*` notebooks uses `except(...)` where `raise Exception(...)` is meant, which is a syntax error; remove or fix that check before running.
- `util.plot_distribution(sample)` refers to `samples` in its body.
- Excel access through `xlwings` is not very clean or efficient. Wrapping it in a class would make the code easier to use and maintain.
- There is repetition across the notebooks that could be turned into functions.
